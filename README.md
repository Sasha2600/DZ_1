# Агент поддержки (LM Studio + OpenAI SDK)

Проектирование архитектуры агента: 

Цикл **Reason → Act → Observe** с роутингом между дешёвой и продвинутой моделью,
с использованием OpenAI-compatible API.

## Требования

- Python 3.14
- Пакеты `openai` и `python-dotenv`:

  ```bash
  pip install -r requirements.txt
  ```

- Запущенный LM Studio с включённым Local Server (по умолчанию порт 1234).

## Настройка

1. Скопируйте `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

   Файл `.env` уже в `.gitignore` — секреты не попадут в git. Все параметры
   (`agent.py` их читает через `os.getenv` с дефолтами из `.env.example`):

   | Переменная | Назначение |
   |---|---|
   | `LM_STUDIO_BASE_URL` | адрес OpenAI-совместимого сервера (LM Studio или облачный провайдер) |
   | `LM_STUDIO_API_KEY` | ключ доступа (для LM Studio — любое непустое значение; для облачного API — реальный секрет) |
   | `CHEAP_MODEL` / `ADVANCED_MODEL` | идентификаторы моделей |
   | `MAX_ITERATIONS`, `REQUEST_TIMEOUT_SECONDS`, `TOTAL_CYCLE_TIMEOUT_SECONDS`, `MAX_DIALOG_TOKENS_APPROX` | защита от Dead Loop |

2. В LM Studio загрузите (как минимум) одну модель, а лучше две:
   - лёгкую/быструю — для классификации, поиска и валидации;
   - более крупную — для генерации сложных ответов.
3. Откройте вкладку **Local Server**, нажмите **Start Server**.
4. Впишите точные идентификаторы моделей (Model Identifier) в `.env`:

   ```
   CHEAP_MODEL=...
   ADVANCED_MODEL=...
   ```

   Если модель одна — укажите одно и то же имя в обеих переменных.
   Можно использовать одну и туже модель, выделяя разный reasoning_effort(Для задач средней сложности и выше)
## Запуск

```bash
python agent.py
```

Пример диалога:

```
Вы: как оформить возврат?

[Outcome.ANSWERED] (итераций: 1)
Чтобы оформить возврат, напишите в поддержку номер заказа и причину
возврата в течение 14 дней с момента покупки. Деньги вернутся на исходный
способ оплаты за 5-7 рабочих дней. [источники: faq-refund]
Источники: faq-refund
```

## Что демонстрирует код

- `classify()` — этап Reason (guardrail + определение сложности/риска).
- `retrieve_context()` — этап Act (поиск в базе знаний; в демо — keyword-скоринг,
  в проде — векторный поиск).
- `generate_answer()` — этап Act (роутинг: простые+уверенные случаи → дешёвая
  модель, остальное → продвинутая).
- `validate_grounding()` — этап Observe (проверка, что ответ подтверждён
  контекстом, а не выдуман).
- `run_agent()` — оркестрация цикла с защитой от Dead Loop:
  - лимит итераций (`MAX_ITERATIONS`);
  - таймаут на весь цикл (`TOTAL_CYCLE_TIMEOUT_SECONDS`);
  - таймаут на отдельный вызов модели (`REQUEST_TIMEOUT_SECONDS`);
  - обнаружение повторяющегося запроса (защита от зацикливания);
  - грубый лимит токенов диалога (`MAX_DIALOG_TOKENS_APPROX`).
